rust-toast

Native notification cards for Rust apps on Windows and macOS.

Cards stack in a corner of the screen, sit over every window and never take focus. They are your app's own windows, not the OS notification centre. The desktop below runs the same motion: hover it, drag a card away, flood it and scroll through.

What it does

One line each.

  • Stacks in a cornerAny of the four corners of the screen the pointer is on, over every window.
  • Never takes focusCards don't activate: whatever you were typing into keeps the keyboard.
  • List, then deckThe three newest show in full. Older ones fold into a deck in the corner, with a count.
  • Hover to openHovering opens the whole stack into one list and pauses every timer.
  • Scroll and drag through manyWhen more are up than fit, the wheel or a vertical drag moves through them one card at a time, with a deck at each end.
  • Drag to dismissThrow a card sideways or flick it. The stack stays open a moment so you can throw the next one.
  • ButtonsAction and confirm cards carry up to two buttons; made sticky, they stay until answered. The answer runs your callback.
  • SoundsOne for success, one for failure, one for cards that ask something. On, off and volume are the user's setting.
  • Confetti on successAn optional burst from success cards, skipped when the OS asks for reduced motion.
  • Light, dark, glassTwo palettes you can override, or follow the OS. Real glass: acrylic on Windows 11, a visual effect view on macOS.
  • Out of screenshotsCards are left out of screenshots and screen recordings by default.
  • Replace in placeA card with an id updates the live one instead of stacking a second.

Use

Add it as a git dependency. The package is rust-toast; the library is toast.

[dependencies]
rust-toast = { git = "https://github.com/StephenSHorton/rust-toast", tag = "v0.3.0" }
use toast::{Action, Config, Kind, Note};

// Once, at startup: the look (palettes, scheme, corner radius, glass).
toast::configure(Config { app_name: "My App".into(), ..Config::default() });

// A card that goes away by itself.
toast::post(Note {
    title: "Build finished".into(),
    body: "All tests passed.".into(),
    kind: Kind::Success,
    ..Note::default()
});

// A card that stays until answered. The first button is the primary one.
toast::post(Note {
    title: "Allow the agent to run git push?".into(),
    body: "It wants to push feat/new-ui to origin.".into(),
    kind: Kind::Warn,
    actions: vec![Action::new("Allow", || println!("allowed")), Action::close("Deny")],
    sticky: true,
    ..Note::default()
});
  • toast::set_options takes the user's settings: on or off, corner, sound and volume, confetti.
  • Note::id replaces a live card in place; toast::close(id) takes it down.
  • Cards that aren't sticky expire on their own; hovering the stack pauses them.
  • Config::capture_exclude (on by default) keeps cards out of screenshots and recordings.

Motion settings

The timings and thresholds in the demo are settings, not fixed: how many cards show in full before the rest fold, how far folded cards peek out, how far a drag travels before it picks an axis and before it dismisses, how fast a flick has to be, and how long the stack stays open after a throw. The demo uses the values the motion was designed with.

Platforms

  • Windows 10 and 11: layered, topmost, WS_EX_NOACTIVATE tool windows on one dedicated UI thread with its own message loop. Nothing to wire up: the first post starts it.
  • macOS: non-activating NSPanels at status-window level, on the AppKit main thread your app already runs (Tauri does). Don't start a second NSApp loop.
  • Everywhere else: every call is a no-op, so shared code needs no cfg.
